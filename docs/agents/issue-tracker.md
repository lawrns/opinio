# Issue tracker: GitHub

Specs and implementation tickets for this single repository live in lawrns/opinio GitHub Issues, as requested by Chief. Use the GitHub MCP connector for issues and comments so the OpenBot app is the author. Never substitute gh for GitHub writes.

Read full issue bodies and comments before changes. Specs/tickets use ready-for-agent only after requester approval; during planning they remain local review drafts. Publishing a draft does not authorize building. Parent specs link their child tickets; children link the parent. Prefer native blocking relationships where supported; otherwise put explicit blocking issue links in each body. Do not close or modify a source parent merely to publish its breakdown.

PRs as a request surface: no. For this task, no builder handoff before Chief review; future implementation is separate draft PRs, no merge or deploy without authorization.
